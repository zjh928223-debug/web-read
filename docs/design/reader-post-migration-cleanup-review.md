# 迁移后清理独立只读审核方案

日期：2026-10-01（Asia/Shanghai）。状态：审核标准已制定，施工与本轮审核尚未执行。

施工依据：[迁移后清理施工方案](reader-post-migration-cleanup-plan.md)。

## 1. 审核对象和边界

标准 Tailwind + shadcn-vue 原位换肤原定范围已完工，独立验收 PASS。
本轮只审迁移后代码清理的完整性与当前外观/操作保持，不重新审判旧任务，
不设计新主题，不要求全应用改为 utilities 或消灭所有 CSS。

由用户/调度者安排独立只读审核对话，执行者自查不算独立审核。
审核者不改产品/测试/配置/文档/任务状态，不提交、不 build、不自行修复，
不新建聊天或代理、不用 worktree、不 promotion。
可以读取开场副本、产物和源码，在隔离浏览器补查，临时证据仅写本轮独立 Temp 目录。

先读 AGENTS.md、施工方案、执行交接和
`docs/architecture/review-loop-and-evidence-validation-lessons.md`。
审核发现必须关联以下 CP 条款或具体 P0–P2 产品/数据/回滚失败；
不得以个人审美、CSS 行数/important 数量、全 CSS 清零、未用某个组件库组件作为失败依据。

## 2. 开场与审核顺序

1. 核对最终 HEAD/dirty、执行开场副本和 SHA-256；区分本轮 diff 与开场已有换肤/其他工作。
   不要求 clean tree，不以 HEAD 相同推断文件内容相同。
2. 阅读清理台账：C01–C06、起始候选、执行新增候选、删除/合并/有据保留/未确定的结果。
3. 对照当前源码核实消费者链与测试调整，尤其多选择器部分删除、变量动态前缀、
   条件渲染/Teleport 和专用原生控件。
4. 审查 before/after 源码与生产证据的环境一致性、实际加载资产和两个入口。
5. 独立复核第 4 节高风险矩阵；无需机械重复执行侧每个同族元素，但缺失的必要项
   不能由抽查其他对象 PASS 抵消。
6. 输出 CP01–CP10、清理台账闭合情况、视觉/操作保持和未测项；不替执行者改状态文件。

## 3. 固定审核条款 CP01–CP10

每项填 PASS / FAIL / NOT_VERIFIED，不能用含糊的“基本通过”替代。

| 编号 | 通过条件 | 必需证据 |
| --- | --- | --- |
| CP01 工作区与基线保护 | 只在优化树实施，无 worktree/提交/promotion；开场 dirty 和非本轮工作保留；存在可恢复开场副本 | 当前状态、本轮逐文件 diff/副本、产物与进程记录；不使用 reset/clean |
| CP02 候选完整对账 | C01–C06 的起始候选与同类扫描新增候选都有删除/合并/有据保留；未确定=0 | 逐分支/属性/函数台账与源码对应；无消费者结论包含动态/条件生成链核对 |
| CP03 迁移旧控件分支收口 | 已无消费者的旧按钮规则退出；仍有消费者的通用分支有具体保留依据；没有靠 owner 排除留下无人使用的重复实现 | 根/SRS/预习当前模板与 DOM 生成链、旧分支去向；专用 switch、badge/file/bubble/video 保留 |
| CP04 退役界面链退出 | 无节点的 helper/style-editor 选择器和独占生成/绑定链退出；现行 chunk editor/facades/init/dispose 保持 | 当前 DOM/JS 接线与差异；旧链无调用依据；chunk 编辑/保存/关闭/焦点真实证据 |
| CP05 变量生成与消费一致 | 确认无消费变量的 CSS 定义、theme 生成/清除及独占计算同步退出；存储/正文/有效 custom 清理不变 | var()/JS/前缀组合核对、light/dark/custom 两亮度切换及恢复、有效变量与存储格式 |
| CP06 覆盖合并与加载合同 | 同一上下文的可消除历史覆盖已收口；保留有具体理由；未跨状态/media/layer误合并；入口/顺序/首屏合同保持 | 前后 matched/computed 来源、有效属性并集；reader 与 standalone SRS 的真实生产加载链 |
| CP07 视觉和布局保持 | 默认/交互/状态外观无设计性变化；36px 配方、SVG、换行例外、固定浅色学习页和专用内容语义保持 | 同环境1280/390、适用主题/owner/Teleport 的前后属性与截图；无新裁切/遮挡/入口变化 |
| CP08 操作和运行时保持 | chunk editor、录键/Escape、主题恢复、播放/跳句、学习入口、关闭/焦点正常；保留 glass 初始/动态/重初始化/dispose；无新增运行错误/启动布局回归 | 真实入口/合成媒体动作；正反生命周期测试；启动 CLS < 0.01 与错误记录 |
| CP09 检查与生产证据有效 | 必需 focused 检查通过，测试未为删代码而削弱；当前源码和新 Temp 产物两入口的必要矩阵齐全 | 命令实际日志/替代逐项映射、after-dist 身份及实际加载资产；过时夹具替换为当前消费者 |
| CP10 交付和状态诚实 | 本轮改动/清理台账/保留理由/回滚/限制齐全；必要项 FAIL/NOT_VERIFIED=0；不混称旧验收、全应用统一、日常替换 | cleanup-handoff、最终 diff、证据链接和未测列表；未运行命令仍为 NOT_RUN |

CP03 并不要求所有 `:not([data-ui-owner=...])` 消失：保留消费者可需要排除已迁移 owner。
CP06 并不要求相同 selector 只出现一次：media/state/不同层及首屏到挂载阶段的重复可成立。
CP02 的“有据保留”必须对应当前消费者/合同，不能以不确定为由改名关闭。
本轮必要子项不能被大项 PASS 掩盖；无法查明的清理候选或受影响状态保持 NOT_VERIFIED。

## 4. 独立复核最小矩阵

默认读执行侧 after-dist 并核对其确实包含最终源码；不自己写 dist。
使用新 context、导航前业务请求拦截、SW block、合成媒体/学习数据，未知请求阻止。
不使用用户 profile，不实际下载、AI、删除、保存后端设置或持久化真实评分。
前后环境包括字体、缩放、browser version、viewport、deviceScaleFactor 和状态一致。

1. **主壳与首屏**：reader 1280×800/390×844，浅/深；工具栏全部分组、主题/素材/学习入口、
   选中与录键状态、SVG 尺寸；确认首屏几何未被删，启动 CLS < 0.01。
2. **主题与变量**：通过实际按钮进入 custom-light/custom-dark，修改五色并重置、切回浅/深、
   刷新隔离上下文；核对 mode 属性和有效变量清理。对比正文色与学习固定浅色。
3. **保留 runtime**：打开 chunk 样式弹窗，数字/颜色/阴影开关，关闭/Escape和焦点返回；
   打开真实 Toast 表面，核对玻璃消费者仍存在。生命周期测试包含首次、动态、重新 init 与释放。
4. **素材覆盖合并**：实际入口打开素材面板，查看受合并影响的 log/title/header/backdrop、
   task 失败/完成/pending、设置/quality/notice；390px可滚动/可关闭。比较获胜来源，
   不能用只加载主工具栏替代素材面板。
5. **学习控件**：reader 内 SRS 与 standalone SRS 均打开，预习/设置/shortcut 打开；
   代表性播放、答案揭示、禁用/等待、录键取消、自然换行、中文 switch 和评分按键可达。
   模拟评分契约只证明 UI 语义，不能声称真实持久化成功。
6. **保留区防误删**：选择受根通用规则删改影响的 badge、bubble、video/file 或词汇/AI窗口，
   审查全部受影响消费者的执行证据，并独立复查至少一项每种删改模式。
   静态判死的规则不制造假节点；仍消费通用规则的对象必须有正向证据。
7. **真实播放**：可解码合成 WAV 经产品按钮播放/暂停、上一句/下一句，观察自然时间推进、
   跳句目标与高亮。强设 currentTime、8字节RIFF、仅 forceUpdateUI 不足。

属性比较按施工方案 V01–V08，不为每个同族按钮重复采样；不同 owner、Teleport 根、
两个生产入口不得互相代替。矩形测量舍入约1 CSS px可解释，文字换行/裁切/顺序变化不豁免。
视觉截图与 computed/matched 证据互补，不能用 class 或 screenshot 单独证明全部合同。

## 5. 测试和证据的裁决

- `style-editor-module-check` 不应继续要求旧生成器/旧 inline margin 存在；
  应验证旧链已退役而当前 chunk editor 接线保持。源码布局断言与真实操作证据分别记录。
- `glass-effects-check` 原 helper/style-editor 夹具改为 chunk modal/Toast；
  不得删除保留消费者正向断言，只留下“不装饰迁移面板”的反向断言。
- focused PASS 不能替代实际 browser 外观/行为；静态变量零引用不能证明实际旅程成功。
- 正式 verify:vite/verify:production-preview 是否运行按真实命令日志判断。
  替代矩阵可以覆盖本轮必要合同，但要逐项说明，不得把命令 NOT_RUN 改成 PASS。
- 完整 npm test、live TTS/WhisperX/AI/跨机持久化不是本轮自动新增门槛。
  未运行、未验证如实保留；具体清理造成的P0–P2回归仍必须阻止通过。
- 历史 PASS/FAIL/NOT_VERIFIED 和 C04/C06 不追改；旧行为证据可用于未受影响部分，
  本轮删除/合并所影响的样式必须由当前源码与最终生产产物支持。
- 可校验文件存在/身份/明确状态，但不编写解析日志推断旅程真实发生的第二套验证器。
- 只读审核默认不裸跑会写仓库/数据的 build/verify；补查证据保存在独立 Temp，
  现有产物身份不足则报告 NOT_VERIFIED，不自行构建补成 PASS。

## 6. 发现、结果和停止规则

发现格式：

```text
[优先级][CPxx] 文件:当前行号
对象/入口/主题/状态 -> 实际结果 -> 既定要求 -> 最小修复与复测
证据路径；是确认缺陷还是待验证疑点
```

美观/未来拆分建议单列，不标成必修P2。历史行号仅作定位线索，最终报告使用当前行号。

最终报告包含：

1. **迁移后清理：PASS / FAIL / NOT_VERIFIED**，附 CP01–CP10 及必要子项。
2. C01–C06 台账：删除/合并/有据保留/未确定统计和具体保留对象，不能只报减了多少行。
3. **当前外观与操作保持：PASS / FAIL / NOT_VERIFIED**，附源码/生产两入口覆盖及未测项。
4. 实际命令结果、限制、剩余最小工作、开场副本与回滚依据。
5. 明确：标准原位换肤仍为既有原范围PASS；未发布、未替换日常版。

只有全部适用 CP PASS 且本轮必要项 FAIL=0、NOT_VERIFIED=0、未确定=0，才能宣布本轮完成。
有确认缺陷为 FAIL；只有关键缺证据为 NOT_VERIFIED；两者并存报告 FAIL 并列证据缺口。

同一任务连续两次修复/复审失败，停止自动迭代并向用户重评；不静默第三轮。
支持脚本约500行以上或审核基线两倍以上触发范围重评，不继续堆解析/断言。

> 不 build、不提交、不创建聊天或代理、不 promotion。分别给清理和外观/操作保持结论，
