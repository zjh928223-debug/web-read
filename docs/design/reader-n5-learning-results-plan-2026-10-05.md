## 用户实际使用顺序

读完文章 → 点击“本篇学习成果整理” → 候选/进度读取后自动发起必要精简，同时显示本次候选及原义 → 调整本次参与的词/短语、逐项对比原义与精简义 → 确认只加入单词或加入单词与短语 → 后台保存 → 看实际结果 → 重开能看到已处理与新增。

打开窗口、移动焦点、查看释义和自动精简均不代表已加入词库，也不代表熟悉。关闭窗口不等于“本篇不加入”。后台任务受理不等于全部保存成功。“本篇候选已处理完”也不等于所有候选都加入了 SRS。

施工顺序与使用顺序不同：先确认保存/恢复可靠，再接自动精简，防止自动请求先行而恢复与结果状态仍不清楚。

## 身份、状态和数据关系

同一个英语词不一定是同一个学习目标。需要同时保留：本篇 source/job 身份、标注 target、词条/语言/单词或短语类型、目标词义、实际语境。不能按词面一把去重，也不能因切换原义/短义生成新词义或重复学习单元。

词库/语境、学习单元与 SRS 状态、文章整理进度分别由既有服务拥有。进度是对已发生操作的记录，不能代替词库和学习记录的真实读回。article completion acquisition 会生成相应学习事件与复习状态，沿用既有合同；它不是全文章每日学习统计，也不等同“熟悉”。

| 状态层 | 至少区分 | 必须避免的误解 |
| --- | --- | --- |
| 窗口读取 | 读取中、读失败、候选就绪 | 读失败展示“0个候选” |
| 本篇概况 | 初次待处理、已有处理且新增、全部已处理、无有效候选 | 只有一串零或无差别重新开始 |
| 单项选择 | 本次参与、本次未选、本篇已跳过、已入库、需要明确重新学习 | 颜色变浅代表所有不同效果 |
| AI | 未精简、处理中、成功可复用、失败/结果无效、结果返回但未保存 | AI失败清空原义，或未保存却说已经完成 |
| 入库 | 未提交、已受理/处理中、完成、部分完成、结果待核对 | 后台受理即宣布全部成功 |

实现可以使用既有字段派生这些呈现，不要求新增统一“大状态机”或第二个持久状态仓库。已处理和新增计数要说明单位是候选目标还是词条；不能把多个语境统计成多个新增词。

## API次数与减少重复请求（2026-10-05 用户补充）

用户要求在不减弱准确性的前提下减少调用，担心一次传入过多内容导致偏差；其他要求认可。以下为当前源码核对和拟采用路线，未修改prompt/产品，未运行合并方案的真实provider对比。

| 环节 | 当前请求机制 | 本次建议 |
| --- | --- | --- |
| 下载后语块切分 | core.py真实路径单独调用_build_input_json_with_gemini；可命中请求缓存，失败可本地回退 | 保留，不与整篇翻译或后续词汇任务一起合并 |
| 中文翻译 | 随后_generate_real_output→generate_zh_for_chunks再发独立请求 | 保留既有固定语块/中文输出校验，N5不重做下载流程 |
| 标注目标的详细解释 | annotation_backfill_template.py默认每批15项；runtime按批调用，暂时错误有重试；新增目标/已完成覆盖有增量与复用 | 在同一小批响应中同时产出详细meaning和短simpleMeaning，分别约束目的；不靠提高批量数减少请求 |
| 整理时短释义 | 目前是独立srs_meaning_refinement请求，一次操作单请求且无自动重试；只处理符合资格且缺合格结果的目标 | 自动检查并复用前一步合格短义；旧数据、缺失/无效短义才补必要请求，显式失败重试只补失败目标 |

因此不是固定“生命周期3次”。在真实模式、无缓存、无重试、一次标注不超过15项且一次整理完成的简单样本中，当前为2次下载加工＋1次标注解释＋1次精简＝4次；拟合并路线中，若标注响应的短义全部合格，为2＋1＋0＝3次。多批标注、分次新增、重试及缓存会改变实际数量，不能把一个UI操作或batchCount当作真实云端调用计数。此前N4短素材实际证明下载切分/翻译链路，没有运行标注解释和整理精简，不作为4→3的实测证据。下载和WhisperX本地转写不计为Gemini请求。

减少的是详细解释后又提交相同目标求短义的独立往返；不会提前让下载模型猜所有未来要标注的词，也不把整篇切分、翻译、词汇解释和精简都塞入一次请求。当前普通标注prompt未要求短义，但result-store、session import/merge、article settlement与srs-candidates已能读取simpleMeaning；源码兼容能力不能替代端到端验证。已有有效原义/短义保留，不能为新prompt版本把旧文章全部重做。

两种输出的语义须分别保留：原解释说明本文语境/用法，短义是实际标注表达的简短中文词义，不能直接压缩语境中的实体指代。例如“the capital”可在原解释说明指北京，短义应为“首都”；不能因合并任务把短义变成“北京”。原义、boundary/type、memoryHint与目标覆盖合同保持，短义附加字段不替换原字段、不改变词义身份。

批量以当前15项作为起点，并同时限制输入上下文与预期输出预算；长语境应进一步拆小，不能只按目标数判断。保留消歧和跨句指代所需上下文；当前按目标所在位置裁剪文章前缀，不直接删成固定一两句。具体预算由00样本和05对比确定，本轮不虚构已验证的token阈值。原始响应中的合格详细解释应能保留，短义缺失/无效不能迫使整批详细解释重跑。复用核对文章、target、实际内容与生成合同，不能按同一词面跨语境直接共享。

在05接入前固定四项对比条件 C1–C4，纳入S13/S14：

- C1：同一模型、同一目标/语境与相同分组，对照旧解释＋独立精简和联合响应；覆盖单词/短语、多义、指代与明确实体、长上下文、超过15项及旧数据。比较真实provider结果的boundary、类型、目标覆盖、详细解释与短义，不用JSON成功或fixture推断词义准确。
- C2：详细解释不因附带短义而省略原学习说明；短义不混淆指代对象、表达含义及上下文义项，满足现有长度/非空资格。可重复观察到的词义退化应缩小分组或回退独立精简，不以“减少次数”压过质量。
