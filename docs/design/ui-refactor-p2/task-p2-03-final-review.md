# P2-03：旧样式清理与最终收口

## 目标、依赖与时间

P2-01、P2-02 完成后执行；按 [总方案](../ui-refactor-p2-plan.md) 结束本轮 UI 重构。施工 20–30 分钟、审核 10–15 分钟，合计 **30–45 分钟**。

本项只做必要清理、少量关联抽查和收尾记录，不重新进行全站审计，不给保留区域追加迁移任务。

## 1. 核对清单，不重复施工

确认普通按钮／输入已共享已有配方；窗口状态、节点和事件保持。P2-01/02 未受后续变更影响的验证可直接引用。有具体控件因复杂性选择保留原生专用样式，写明即可，不要求零例外。

固定保留清单：

- AI 解释历史卡和状态区；结算候选行、朗读／移出／重新学习及缩放把手。
- VideoPlayerFloat 的原生按钮、媒体控件、定位和拖拽算法。
- TranscriptContainer、ChunkModeView 正文结构和专用排版、annotation-bubble 定位。
- CheckPage、PersonalizationShadowPage、当前不可达旧编辑器的原用途。
- 现有 dialog controller、输入／保存服务和 P1-C 已关闭的最小使用检查。

## 2. 清理范围只跟随实际迁移

1. 在 styles.css 搜索本批三个窗口的关闭／普通按钮／输入装饰，确认旧声明是否仍有未迁移消费者。无消费者才删除，有消费者就保留或收窄；不要整块删除 `.vocabulary-preview-dialog` 的公共布局。
2. 复查 learning owner 排除是否覆盖 hover、focus、disabled 和伪元素；检查没有引入新的全局裸 button/input 样式。
3. 移除本批确实不再使用的局部样式或临时调试代码，保留用于行为定位和测试的 class/data。未修改的历史重复代码不顺手分解。
4. 核对新增源码仍在唯一 Tailwind 入口扫描范围内，没有第二套主题或编译配置。无须新增脚本清单框架；仅确实新增既有登记体系要求的文件时维护原条目。

## 3. 最终只抽查这些关联操作

| 范围 | 一次代表检查 | 何时复用 |
|---|---|---|
| AI解释标注、预习、生词整理 | 打开、一个主动作的模拟状态、关闭；短视口下操作区可达 | 本项未改其生效样式则引用 P2-01/02 |
| 学习页／预习设置 | 一个已有按钮的浅色和 focus 外观 | learning-ui.css 的公共作用域有变化时抽查 |
| reader／工作流 | 一个按钮 hover/disabled 和原主题 | 通用旧 button 排除范围有变化时抽查 |
| 视频／释义泡泡等保留区域 | 仅确认涉及它们的共享旧规则仍保留；确受本批 CSS 影响时再查看对应操作 | 没有命中相关改动就不重新测拖拽、音频和整个阅读流程 |

不为总收尾再次运行真实 AI、下载／转写、Host 重启、评分延迟、旧数据恢复或全六域验收。已有入口故障继续单列，不作为本阶段新任务。

## 4. 必要命令和简单修复

本项改了代码：运行 `npm run build`、`git diff --check`，再运行实际受影响的 `verify:annotation-backfill-ai` 或 `verify:vocabulary-preview-ui`。只有索引/启动脚本等真实变更才补其相关检查。本项无代码改动就引用前项结果，不强制空提交、重复构建或完整 npm test。

| 问题 | 最小处理 |
|---|---|
| 删除规则让保留控件失去样式 | 恢复这条仍需要的规则，不顺手把保留控件也迁移 |
| 同一变量出现两个来源 | 留已采用的有效来源，仅删本批产生的重复映射 |
| 特殊控件为了统一需要大改 | 保留原生专用样式，记录例外即止 |
| 构建／本批 UI 发生新增回归 | 修最近的局部修改，只复测受影响范围 |
| 无关历史检查继续失败 | 保留事实，分开记录，不删除断言或扩大修复范围 |

## 5. 执行后审核与最终交付

- [ ] 三个窗口的约定普通控件完成，专用控件保留有明确说明。
- [ ] 样式变化没有破坏本批涉及的点击、输入、焦点、disabled 与滚动；模拟与真实证据分清。
- [ ] 本批退出的旧装饰已处理，仍有消费者的 CSS 保留；没有以删除行数为目标扩大清理。
- [ ] P1-C/P1-D 已收口结果未被重开，没有自动附加下一轮 Host 或全站验收。

在 [P2 总方案](../ui-refactor-p2-plan.md) 末尾追加一段最终交接：修改文件／提交（如有）、采用的共享配方、保留项、实际检查和范围外历史问题。审核只针对上面标准或本次新增的具体功能故障。

达标后的结论为：**本轮 UI 重构按约定范围完成：常用基础控件和目标窗口已有统一样式来源，专用阅读区域和稳定原生控件继续保留。** 这不表示全系统／所有历史脚本通过，也不需要为了这样的表述再开启一轮检查。

最后保留一份这批方案与交接的仓库外备份，避免未跟踪文档再次丢失；是否提交 Git 按用户要求，不自动提交整个工作区。
