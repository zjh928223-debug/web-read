## 1. 本阶段做什么

把常用设置弹窗的按钮、数量输入外观及容器样式接到已有 Tailwind + shadcn-vue 体系，整理相关旧 CSS。**保留现有开关、保存与键盘控制方式，不以换完所有组件为目标。**

具体选择：复用已有 Button、inputVariants、局部语义颜色；原生 number 输入保留，中文展示切换保留原生 switch；已有 createDialogController 继续使用。P1-D 不要求安装 Dialog/Switch，也不建立通用弹窗管理器。若原生控件更简单，接上共享样式就是完成迁移，不算欠账。

本方案取代早期总览中“单独替换完整行为边界”的笼统安排：本批整理容器外观和控件衔接，不安排 Dialog 行为整体替换。

## 3. 源码检查后作出的取舍

| 实际情况 | 简单做法 | 避免的功能退化 |
|---|---|---|
| PassagePreviewSettingsDialog 由 App 的 Teleport 挂到 body，离开 `.srs-review-page`；当前没有接入 dialog controller | 在该弹窗根提供已有学习语义变量和固定浅色标记；保留现有关闭方式 | 主壳深色时按钮误变黑；为了统一控制器改变既有交互 |
| 数量字段用原生 `v-model.number`；当前 Input.vue 只显式处理 trim，没有 number modifier 分支 | 保留原生 input，直接组合已有 inputVariants | 输入变成字符串、空值／范围校验或 Enter 保存改变；为一个字段修改全局 Input |
| 快捷键弹窗初始焦点为原生 button ref，控制器需要真实 DOM | 换 Button 时在本弹窗根查询带标记的真实 button；不顺手改控制器 | focus 方法失效或焦点跑到弹窗外 |
| 快捷键录制在 window capture 阶段处理 Escape，现有 dialog controller 在 document 上处理 Escape | 保留该顺序，录制中 Escape 取消录制，非录制时关闭 | 一次 Escape 既取消又关闭、录键触发后方阅读操作 |
| 中文模式为带两个文案的原生 `role="switch"` 按钮 | 保留节点、aria-checked 和 handler，仅整理局部语义色 | 换通用 Switch 后产生新的事件／键盘语义 |
| AI 样式弹窗在 index.html，style-editor.js 使用 ID 与 inline display | 保留 DOM、ID、显隐控制和几何，收拢容器装饰来源 | Tailwind 的 display/transform 覆盖显隐或居中；实时样式绑定失效 |
| 工作流主面板和 Teleport 质量报告已有两个 controller、pending、焦点恢复，按钮已迁移 | 只整理容器背景／边框／阴影及局部重复声明 | 双重焦点控制、质量报告藏到父面板后、pending 被绕过 |
| CheckPage 和其他旧弹窗仍消费共享选择器 | 已迁移控件逐条退出旧装饰；剩余消费者的规则继续保留 | 改 A 弹窗使 B 弹窗失去样式 |

本批处理上表中的常用窗口。注释补全、词汇预览／文章结算、视频浮层、字幕和 Chunk 正文、当前不可达旧样式编辑器列为保留项，留后续按实际需要处理；D05 不把它们算遗漏。

## 4. 所有任务使用同一套简单修复办法

1. **外观问题：** 先查当前选择器、盒模型和局部变量；改最近的一条规则或补一个本地 class。共享规则仍有消费者，就保留它并让新控件退出，不增加新一轮 important 覆盖。
2. **控件替换引起的问题：** 先保留原生节点并复用配方，或只补一个 DOM 查询／局部绑定适配；不为了完成标签替换重写服务或公共组件。保留原生例外可正常收口。
3. **已有断言绑定旧外观：** 更新对应标签／选择器断言，并核对同一行为仍有效；不要求代码继续符合已经退出的旧外观。
4. **入口被旧 Host 问题挡住：** 用现有隔离挂载或最小样例加载实际组件／样式验证本项 UI。服务可用本地固定返回验证事件、pending 和提示，写明是 UI 模拟，不声称真实持久化。本批没有后台变更时，这足以支持约定 UI 范围通过，不再额外欠一套 Host 验收。
5. **需要复杂修复才能继续：** 优先保留该处原实现，交付其余独立修改，注明一个例外；若自身必要 UI 行为仍坏，就如实未通过该项，给出一个具体修复建议。沿用 AGENTS.md 的现有两轮修复规则，不新建审批、健康采样或自动修复链。

这是简化施工方式，不意味着忽略新增的实际故障：弹窗打不开、不能关闭、遮住保存、重复保存、焦点或快捷键失效仍应修复。只有与本项变更有关的具体问题需要本项处理，历史环境问题不转为新任务。
