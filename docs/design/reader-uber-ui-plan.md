## 2. 统一视觉规范

| 项目 | 采用规则 | 阅读器中的应用 |
| --- | --- | --- |
| 浅色基础 | 白 `#ffffff`、黑 `#000000`、次级文字 `#4b4b4b` | 页面与正文以白色为主；标题与操作文本为黑色 |
| 辅助底色 | 灰 `#efefef`；悬停灰 `#e2e2e2` / `#f3f3f3` 按角色分配 | 次级按钮、分组内选项和轻量辅助区域 |
| 主操作 | 黑底白字、完整胶囊圆角 | 播放、弹窗确认、素材主要操作；每个局部任务突出一个主操作 |
| 次操作 | 白底黑字细边框，或浅灰填充胶囊 | 上一句、下一句、设置、导入等；按角色固定，不能随页面变化 |
| 切换选项 | 未选为浅灰，选中为黑底白字 | 倍速、跟随、中文、聚焦；补充勾选/状态文字与已有语义状态 |
| 输入控件 | 白底、清晰的 1px 边框、8px 圆角 | 快捷键、搜索、普通表单；输入框不随按钮改成胶囊 |
| 卡片与弹窗 | 普通卡片 8px、弹窗 12px；边界清楚 | 卡片不层层套壳；阴影仅用于浮层或确需抬起的表面 |
| 材质 | 实色表面、单层轻阴影，无渐变和装饰光斑 | 清理旧玻璃装饰对新外观的覆盖，保留弹窗遮罩功能 |
| 字体 | UI 采用一致的无衬线字体栈，400/500/700 | 首版系统字体含中文回退；不依赖专有 UberMove 或远程字体请求 |
| 字级 | UI 14px、辅助 12px、面板标题 20–24px 为初始值 | 不照搬展示页的 52–64px 标题；正文保留既有字号/字体设置 |
| 间距 | 以 8px 为主，4px 用于紧邻元素，16px 区分组 | 控件成组对齐，避免每个功能外围再套大容器 |
| 密度 | 桌面常规 36px、紧凑组 32px；触控目标至少 44px | 样板同时检查可读性与密度，再确定最终尺寸 |

参考中的 `#afafaf` 仅用于弱辅助信息，不能作为重要标签、唯一状态提示或普通正文颜色。禁用态应减弱且无法操作；不能与浅灰的可操作次级按钮混淆。键盘焦点在白底、黑底和灰底上都必须可见。

### 深色与语义颜色

深色采用黑色页面、`#111111` 表面、白色主文字与灰色次级文字；主操作和选中态反转为白底黑字。参考深色预览中部分黑按钮与黑背景融为一体，不能原样继承。其导航模糊背景也与文档的实色原则存在差异；本方案选择实色，减少材质混用。

统一的是应用 UI 外观。词汇标记、高亮、评分和错误提示中承载业务含义的颜色继续保留，并验证对比度；不得将学习信息一律改灰。正文用户设置不被主题切换覆盖。当前学习域固定浅色的边界继续保留，其浅色配方与新规范一致；不顺带开发学习域深色模式。

## 3. 阅读页如何组合

先按以下顺序制作独立组合样稿，在实物复审后再确定具体位置：

1. **顶部轻量导航**：素材入口、当前内容名称、学习入口与设置。标题长时可省略并提供完整名称；操作文字不能截断。
2. **播放区**：沿用现有音频控件能力；上一句、下一句、倍速、跟随组成紧凑的播放组。第一步不重写播放器，不引入新的播放状态管理。
3. **阅读工具区**：AI 切分、中文、聚焦组成阅读方式组；标记与预习/SRS 入口按用途分别成组。少用的颜色、阴影和快捷键编辑移入可展开的设置区域，原有触发键仍有效。
4. **正文**：占据剩余主体空间，去掉围绕正文的多层装饰壳。行宽、行高沿用现有可调能力，先解决控制区占高，避免同时改动阅读排版而难以判断效果。

设置收起后仍能看到当前开启的关键模式；所有现有功能有明确入口，不借“简洁”删除功能。展开区域优先采用局部布局与既有焦点机制；如确需新增弹出交互，再使用兼容的现成组件并单独核验焦点与关闭行为。

快捷键设置中 `ArrowLeft`、`ArrowRight` 必须完整可辨。使用合适的组件尺寸/布局宽度配置，不能继续固定为不足以显示文字的 63px。快捷键标识与可编辑输入框区分呈现，避免把全部设置常驻成两排表单。

在 1280×720 下，常用控制区目标为约 200–220px 内，作为样稿比较目标，不通过裁切、缩小正文或隐藏必要操作强行满足。以新拍的同状态基线确认实际改善。窄屏按功能组换行，避免单个“中文/聚焦/阴影”被挤成零散一排。

## 4. 框架和文件落点

| 归属 | 后续允许的修改 | 必须保持 |
| --- | --- | --- |
| `src/components/ui/button/button-variants.js` | 配置胶囊圆角、角色变体、尺寸、焦点与状态样式 | Vue 与原生按钮共用；检查各 size 中的圆角不会覆盖基础配方 |
| `src/components/ui/input/input-styles.js` | 输入框主题、8px 圆角、统一密度 | 输入类型、事件、可编辑行为 |
| `src/styles/workflow-ui.css` | 映射浅/深语义变量、状态与 owner 适配 | `rw:`、局部 reset 和主题隔离；不新增全局 Preflight |
| `src/lib/native-control-styles.js`、`native-input-styles.js` | 必要的配方参数适配 | 共用现有助手；不强制将原生控件变成 Vue |
| `src/main.js`、`index.html` | 对应功能角色选择 variant/size，按确认布局组织控件 | DOM id、运行时查找与事件绑定、脚本顺序 |
| `styles.css` | 收敛旧装饰和布局规则、同步初始占位尺寸 | 作用域明确；避免末尾继续叠加大量覆盖规则 |
| `YouTubeWorkflowPanel.vue` | 相同主题下的素材列表、表单、操作分组 | 上传、任务状态、关闭等已有逻辑 |
| `src/features/learning-ui/learning-ui.css` | 映射固定浅色的 UI 变量和控件规则 | 学习状态颜色、评分语义、持久化与原有主题边界 |

现有 UI 原语主要为 Button、Input、Textarea。方案不假定 Dialog、Tabs、ToggleGroup 已安装；普通状态切换优先沿用现有控件，只有实物需要新的交互原语时才评估添加。旧玻璃装饰模块仅在实际影响新界面时做最小范围处理，不借机改运行时架构。

## 5. 分阶段交付与复审

### 第一步：单一方向的基础控件与小工具栏样板

建议新建隔离目录 `docs/design/reader-uber-preview/`。使用现有 Vue/Tailwind/shadcn-vue 组件机制制作，仅对样稿作用域配置主题；不得提前改产品共享配方。样稿构建输出单独保存，不覆盖主应用 `dist`、根依赖清单或运行服务。所有截图与临时检查文件保存在临时目录。

交付内容：浅色/深色；主、次、普通、选中、禁用、悬停、按下、键盘焦点；搜索与快捷键输入；带真实中文文案的上一句/播放/下一句/倍速/跟随组合；一个简单设置弹窗样例。使用内存假状态，不接入 Host、评分、保存或真实阅读数据。

这次只制作 Uber Inspired 一个方向。先判断胶囊比例、灰阶、中文字体、密度和状态是否满意，不再让执行模型自由挑选配色或重新提供四套风格。

### 第二步：独立主阅读页样稿

沿用第一步通过的配方，将顶部导航、播放组、阅读模式、设置展开区和示例正文组合为完整页面。展示常规阅读、AI 模式和设置展开三种状态。仍使用假数据；不接入真实业务。用户看到整页后确定组合方式。

### 第三步：应用到真实阅读页

将确认后的主题与配方纳入现有共享位置，分开处理控件外观和工具栏布局。每次检查已有修改与调用者，不覆盖其他工作。共享配方会影响素材和学习域，因此即使这一阶段主要改阅读页，也需快速检查受影响页面是否出现明显回归。

保留原生音频控件能力及各控件 id。移动原生 DOM 前核对运行时的查询、父级依赖、事件委托与焦点恢复；出现绑定故障先修复本次变动，不开展无关架构改造。

### 第四步：扩展到素材窗口与常用弹窗

统一素材列表/表单、设置、确认类弹窗以及学习页普通控件。继续保留词汇、评分等专用状态的含义，逐组交付。只有实际复现的问题才进入修复范围，不重开已完成的 Host 维修。

每一步由当前对话复审；执行按既有约定使用新的本地对话、`gpt-5.6-luna / max`，写入串行，不使用 worktree，不预创建后续任务。本规划不派发任务。

## 6. 先约定的轻量验收

- **视觉一致**：黑白灰、胶囊按钮、8px 输入框、12px 弹窗形成一致体系；没有残留暖纸/蓝紫装饰/玻璃光斑混入新区域。
- **状态明确**：普通、可操作的次级、选中、禁用、焦点能区分；浅深色均检查。状态不能只靠轻微灰度差。
- **布局完整**：1280×720 前后使用同一内容和相同状态；另检查 390px 窄屏。完整显示方向键名称，无控件重叠、意外横向滚动或零散断行。
- **阅读优先**：控制区占高明显降低；正文现有字体/字号设置仍有效，不为缩小顶部而牺牲操作可读性。
- **关键行为**：实际接入后检查播放/倍速/跳句/跟随，快捷键编辑和触发，AI/中文/聚焦/高亮，弹窗 Escape/关闭/焦点恢复/滚动输入。涉及学习页才追加本次影响的标记、预习、SRS 保存读回检查。
- **检查按改动选择**：文档阶段不构建；样稿检查独立构建与浏览器交互；产品阶段运行 `npm run build`、`npm run verify:vite`，再按影响选择既有脚本顺序、主题、键盘、玻璃装饰或学习检查。执行前核实脚本与端口行为，避免干扰当前服务。

服务使用优化版配置和 5184/8776，启动前检查现状；不能把旧服务仍在展示的构建当成本次代码效果。截图通过与构建通过只代表相应检查结果，最终仍由用户判断是否顺眼、适合长期阅读。

复审发现应对应上述标准或具体功能故障，不扩展成新的证据平台或复杂门禁。同一任务连续两次修复/复审失败后重新判断边界，不自动开启第三轮。
