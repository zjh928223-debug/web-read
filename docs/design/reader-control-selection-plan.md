## 四个候选方向

| 候选 | 现成组件选型方向 | 本轮比较的问题 |
| --- | --- | --- |
| A 细边框 | 优先采用 shadcn-vue `outline` 的原生外观 | 是否喜欢明确的控件轮廓？ |
| B 柔和填充 | 优先采用 shadcn-vue `secondary` 的原生外观 | 是否喜欢靠底色区分控件？ |
| C 轻微立体 | 查找 Vue 生态现成的立体/raised 变体；具体来源待核实 | 是否喜欢一点实体按键感？ |
| D 苹果液态玻璃质感 | 使用现成 Vue Liquid Glass 组件的透明、折射、高光及阴影效果 | 是否喜欢通透、有玻璃厚度与流动反馈的控件？ |

四组固定相同的文案、顺序、背景和状态样本。优先使用组件现成的小尺寸，并通过组件公开的尺寸、圆角、主题参数尽量统一比较条件。此前提出的 32px 高度、13px 字号、6px 圆角仅作参考；不为硬凑这些数值手写覆盖样式。无法通过公开配置统一的差异应标明。

如果 C 没有找到合适的现成组件，报告选型缺口，由当前对话决定调整候选；不得自行画一个立体按钮冒充框架提供的变体。

先采用中性灰，不自行选定暖纸、青绿、紫色、品牌色或大圆角。D 允许在控件自身使用玻璃材质，不把整张选型板变成玻璃风格。不给某一组额外布置有利的背景、装饰或优先推荐标记。

### D 的具体要求

- 以 Apple Liquid Glass 为视觉参考，挑选具备通透材质、边缘反射与折射感、轻微厚度和悬浮层次的现成组件，不宣称复现 Apple 原生渲染。
- 不能只降低按钮透明度；边缘亮暗、背景透过材质后的变化，以及按钮与背景的分离感都应可见。高光和阴影控制在控件附近。
- 悬停、按下时可有轻微高光和表面反馈，不增加持续流动、自动扫光或大幅缩放；尊重减少动态效果设置。
- 文本与图标保持清晰，不随背景一起模糊。开启、主要动作、禁用状态同样需要明确表达，不只依赖透明度差异。
- 为观察背景对材质的影响，提供全局统一的“纯色 / 低对比明暗纹理”背景切换；四组同时切换到同一背景，纹理只服务于比较，不代表已选定产品背景。
- 直接使用选定组件的公开 API，例如圆角、模糊、透明度和折射强度。不得手写玻璃 CSS、SVG 位移滤镜、Canvas、WebGL 或着色器来补足效果。沿用现有按钮与输入语义，效果层不得拦截交互；组件不支持的状态或浏览器回退应如实说明，不静默变成自研特效任务。

### 技术可行性核查（2026-09-26）

- 当前项目使用 Vue 3、Tailwind v4 和 shadcn-vue，按钮配方、原生控件助手与局部 CSS 变量允许增加玻璃视觉处理，无需更换 UI 框架或转换所有原生控件。当前按钮配方尚无现成的玻璃变体。
- Tailwind 官方支持背景模糊、饱和度以及自定义 SVG 背景滤镜值，说明技术栈可以承载效果。用户已明确选择现成组件路线，不据此自行实现滤镜。
- Inspira UI 提供面向 Vue 的 Liquid Glass Effect，shadcn-vue 的社区注册表目录也收录 Inspira UI。已读取 `https://inspira-ui.com/r/liquid-glass.json`，源码可获取；但其源码引用 `@inspira-ui/plugins`，并使用未显式导入的 Vue API，不能依据注册表的空依赖列表宣称可在本项目零适配运行。旧文档链接及新注册表域名下的同名条目本次返回 404，交付应以实际可访问的源为准。
- `@aslanonur/liquid-glass-vue` 是另一候选。核查时 npm latest 为 `1.1.3`，`dependencies` 为空，`peerDependencies` 为 `vue: ^3.0.0`；公开组件提供 `cornerRadius`、`blurAmount`、`displacementScale` 等参数。这只确认包元数据与 API 文档，不代表已经验证质量或浏览器兼容性。
- Inspira 的该组件文档以 Chromium 为增强效果目标，Safari / Firefox 使用磨砂玻璃回退。不能把普通 `backdrop-filter: blur()` 的支持范围等同于 SVG 背景位移滤镜的支持范围。
- 当前已核对文档和项目源码，尚未在阅读器中验证这些第三方实现的视觉、性能或兼容性。D 的实际效果由执行模型在隔离样稿中展示后复审。

## 每组必须包含相同样本

1. 普通动作：上一句、下一句。
2. 主要动作：播放，点击可切换到暂停演示，但不播放音频。
3. 开关：跟随，具备明确的开启和关闭状态，使用 `aria-pressed`；开启状态除底色外还应有文字或图形线索。
4. 禁用动作：AI 解释，以原生 `disabled` 表达；在旁边明确注明这是禁用样本。
5. 输入框：`ArrowLeft`、`ArrowRight` 和单字符 `M`，完整显示；允许临时编辑，不保存、不接管真实快捷键。
6. 下拉框：0.85×、1.0×、1.25×，只演示控件外观和选择行为。
7. 图标按钮：关闭，具有清晰的可访问名称；无真实窗口关闭副作用。

允许选择一种候选并在当前页面显示“已选 A/B/C/D”；选择仅在内存中保留，不推断为用户已批准产品落地。

不制作素材窗口、设置系统、文章正文、工具栏布局或整页样稿。输入框不增加校验业务，开关不绑定产品状态。

## 执行前确定的复审标准

- 四组差异清楚，其他比较条件一致；真实使用中文文案，具名快捷键不截断。
- D 在纯色和低对比纹理背景下均保持文字、图标与状态可辨认，能看出玻璃边缘和层次；不以模糊文字或牺牲可读性换取效果。
- 普通、悬停、键盘聚焦、开启、禁用、主要动作之间可辨认；不能将开启状态做得像禁用状态。
- 正常 Tab 顺序和可见焦点；禁用动作不触发，输入与下拉框可正常操作。
- 1280×720 下便于横向比较；390px 宽度下可顺序查看，没有页面横向溢出、文字裁切或控件遮挡。
- 页面能独立打开，无相关控制台错误；没有业务 API 调用或保存行为。
- 新增文件只在指定样稿目录；现有产品文件、用户修改和运行服务保持原状。

复审报告分别说明“是否满足这些交付要求”和“仍需用户选择的审美问题”，不得用 PASS 宣称用户已经满意。
