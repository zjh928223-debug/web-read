# 解释结构约束与分批恢复

## 实施前固定的验收范围

1. 普通及短文联合解释请求携带 JSON Schema，约束目标编号、boundary、type、meaning、memoryHint（联合解释可附 simpleMeaning）；原文和位置由本地按编号回填。
2. 本地拒绝缺少/空白释义、错误字段类型、重复编号；丢弃未知编号和多余字段。只重试缺失或无效目标，保留同一响应中有效目标；整段无法解析时重试当前待处理批次。
3. 默认最多两次额外尝试，复用原有可配置上限；非法响应重试绕过坏缓存，429/503 等暂时失败仍受次数、取消与总时限约束，不对鉴权等永久错误盲目重试。
4. 每批及每次部分成功以原子 JSON 保存验证通过的目标。再次开始/后台重建后，只续传未完成目标；模型、服务地址、提示词、文章或标注上下文变化不可复用错误进度。
5. 失败不覆盖已有完整 latest/version 结果，不把部分结果标为完成；失败提示说明已保存/未完成数量。全部通过后按原目标顺序合并、保存并沿用现有自动导入。
6. 覆盖成功、漏项、重复/未知编号、错误类型、坏 JSON、坏缓存绕过、重试耗尽、取消、存储失败、重建恢复、输入变化隔离，以及 SDK 参数传递和浏览器自动导入。

独立 SRS 短义修订继续保持已有单请求/零额外重试合同。本次不修改 IndexedDB schema、词典领域、模型选择规则或日常 N5 副本。先离线/注入响应测试；真实网络验证与离线证据分别记录。发布到优化 5184。

## 实现边界

增加解释输出合同与分批执行/进度模块，保持 runtime 负责生命周期和最终发布。进度按完整输入、模型、服务地址、提示词和合同版本指纹隔离，使用既有 DurableJsonRepository 原子提交。完整结果继续使用现有 latest/run 接口。
