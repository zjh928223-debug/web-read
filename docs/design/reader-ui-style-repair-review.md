# UI 样式维修完工独立审核方案

日期：2026-09-29。状态：验收标准已固定，维修及本次完工审核均未执行。

施工依据：[reader-ui-style-repair-plan.md](reader-ui-style-repair-plan.md)。全应用调查继续使用 [reader-ui-full-style-audit-plan.md](reader-ui-full-style-audit-plan.md) 的 C01–C08；原换肤范围依据原 inplace-plan / inplace-review 的 A01–A10。

## 1. 角色、范围与证据边界

由用户或调度者安排一个新的独立只读审核对话。审核者不修改产品/测试/配置/文档/任务状态，不提交、不自行修复，不创建任务/代理，不使用 worktree。

本次审核三个结果：已确认缺陷是否修好；本轮全应用调查是否补齐；仍有哪些明确保留/新增建议/未验证。三个结果分别报告，不能互相代替。

本轮已确认 F01 是 `.transcript-header` 的半透明表面、光斑和内高光；F02 是 `.controls/.extra-controls` 的 `::after` 内高光。原 A04/A05 及原施工 4.2.7 支持修复。其他报告候选须经执行侧取得真实证据后才能成为新增 S3。

现有独立基线区分两种环境：当前源码壳加 glass 初始化的隔离样本，以及读取现有 dist 的真实 reader 入口。前者不是完整应用，后者不是新构建；两者对 backdrop-filter 的结果不同。完工审核不能忽略这一区别或把定向样本冒充全应用巡检。

## 2. 开场顺序

1. 读 AGENTS.md、施工方案、本审核、原完整调查方案及执行交接。现场核对 HEAD、dirty 清单与执行开场副本。
2. 将本轮维修 diff 与此前 27 个文件的原位换肤改动区分。审核新增/受影响范围，不要求 clean tree，不把旧未提交差异全算给执行者。
3. 查完整容器/子视图/元素表及 S1–S5 分类，核对 reader 和 standalone SRS 两入口、Vue/Teleport/动态 DOM/CSS 消费者对账；旧 28 项和六张图不是上限。
4. 阅读执行侧前后截图、computed/matched rules、命令日志、生产入口资产与失败记录。核对文件身份与内容，不只读 PASS 字样；缺失的临时文件只对必要范围补测。
5. 只读默认不运行 build 或会写仓库/数据的 verify。独立浏览器复核使用新 context、导航前拦截、合成响应和 Temp 证据，不使用用户 profile 或真实 sample。不能安全复核时具体标 NOT_VERIFIED。

## 3. 固定维修验收 R01–R09

每项填写 PASS / FAIL / NOT_VERIFIED。部分完成需附范围，不能用“部分”替代正式状态掩盖缺口。

| 编号 | 通过条件 | 最小审核证据 |
| --- | --- | --- |
| R01 隔离与工作保护 | 新 context；导航前处理 HTTP/外部/未知请求，SW/WS 不绕过；仅合成业务；保护开场差异、日常树和真实数据 | 审查实际上下文与 route 代码、请求摘要、仓库差异。新建标签或初始 Cookie 为零单独都不够；不得要求万能日志验证器 |
| R02 F01 表面修复 | transcript-header 浅/深/custom 的目标表面使用现有实色映射；无模糊、光斑、渐变或装饰 inset 高光；定位/布局/功能阴影保留 | 当前源码与新产物实际页面的 computed、匹配规则、稳定截图及前后对照；不能只检查 class 或 filter |
| R03 F02 伪元素修复 | controls/extra-controls 的装饰性 ::after 消失，::before 不复发；不误删非目标消费者 | 两个伪元素的 content/display/实际绘制属性及来源，真实页面浅/深观察。content:none 时遗留但不绘制的 background 属性不单独构成失败 |
| R04 运行时生命周期 | 三个目标面板首次/动态插入/重新 init 均不重新装饰；保留面板正常；dispose 释放 observer/RAF/指针监听 | 审查 glass-effects 改动和行为测试，保留正向消费者断言；必要时小范围独立执行隔离样本。不要要求移除整个 glass 模块 |
| R05 其他修复与例外 | 新增 S3 均映射原条款或具体 P0–P2；例外按属性；S4 未擅自施工；所有确认缺陷有对应复测 | 每项入口、状态、获胜规则、原要求与维修 diff。旧 CSS 存在、个人审美或共享组件缺失均不单独判错 |
| R06 控件与主题 | 原 default/icon/input 配方和层顺序保持；learning 固定浅色；custom 及正文颜色语义保持 | 审查影响面。普通按钮不只看 36px，还看 padding/gap/font/radius/SVG；只对相关上下文抽查，不对每个相同按钮重复截图 |
| R07 操作与布局 | 原入口、顺序、分组、id/ref/事件不变；桌面/窄屏可达，无新裁切/遮挡；录键、关闭与焦点正常 | 合成 reader 关键动作和本轮改动窗口的行为证据；允许自然换行/正文下移，不能要求恢复旧紧凑布局 |
| R08 验证和生产一致性 | 直接相关 focused checks、当前源码加载及新生产入口有有效结果；修复模式在生产不回退；既定 CLS 门槛有身份明确的证据 | build/verify 日志、实际加载资产、两个入口及相关异步 CSS。源码内存样本、旧 dist 或孤立按钮不能替代新产物全部相关证据 |
| R09 交付和范围诚实 | 本轮 diff/基线/前后证据齐全，完整调查表与 S2/S4/S5 可查；未测项和历史失败保留；无自动提交/promotion | 审查执行交接与现场状态；核对最终三种结论的措辞，不能把一次修复 PASS 写成全应用统一 |

补充：默认主题普通 UI 的 neutral 要求不覆盖用户自定义正文色；合法的状态色、媒体/颜色/文件原生控件、专用阅读几何不因本审核变为新迁移要求。目标玻璃装饰消失即可，不要求全部 box-shadow 都为 none。

## 4. 全应用调查充分性单独判定

按原 C01–C08 逐项填写 PASS / FAIL / NOT_VERIFIED，并给具体证据。C 表用于判断调查是否充分，R 表用于判断本次维修是否符合约定。

- C01：从入口/运行遍历/CSS 消费者三线发现，当前候选有清单去向；排除对象有依据。
- C02：每个当前容器及不同内容子视图有实际打开记录；受阻保留，不能用抽样替代执行侧全表。
- C03：外壳、文字、标签、状态、kbd、switch 等均有元素记录，不只统计 Button/Input。
- C04：S1/S3 有最终属性与获胜来源；class、h-9、截图或 Coverage 单独不够。
- C05：S2/S3/S4/S5 分开，例外具体到属性；复合控件自动高度不豁免全部装饰。
- C06：1280×800/390×844、适用主题和真实状态已覆盖；设置 class 不能冒充交互发生。
- C07：两个生产入口的加载链/顺序、相关覆盖模式和疑点容器有生产证据；产物不明则未验证。
- C08：合成/真实/样本/历史证据范围清楚，工作区与数据保护成立，不扩大为 Host 完整验收。

审核者核对全表、独立检查易遗漏路径与关键风险，不机械重跑执行侧所有旅程。执行侧表中缺某个必要界面，不能由审核者抽查别处通过来抵消。

## 5. 独立复核的最小矩阵

1. 在当前可核验页面观察三个 reader 面板：浅/深，桌面/390px；用实际主题按钮进入 custom，核对 mode 属性、面板映射和正文色。等待过渡稳定，避免截过渡帧误判深色。
2. 指针进入、移动、离开目标面板后重查伪元素和光斑；复核动态节点/重初始化的隔离行为证据。不要强行在业务页面注入 DOM 后宣称原入口已验证。
3. 对本轮每种新增 S3 修复模式，至少选真实消费者复测默认与出问题的状态。共享规则的所有独立 owner/Teleport 上下文都必须有执行证据。
4. 检查播放/跳句/跟随/高亮/录键/chunk 相关控件事件及弹窗关闭/返回焦点。使用合成数据，不能触发真实评分、下载或设置保存来证明换肤。
5. 新生产 reader 重复关键修复属性；standalone SRS 以请求拦截提供合成词库后打开真实入口。若学习样式完全未改，原有效证据可用于未受影响行为，但本轮调查 C02/C07 所需页面和产物证据仍须存在。
6. 检查现有产物曾出现的“源码有标准 backdrop-filter、产物仅 prefixed”的区别已不影响修复目标。不得要求为恢复已退役玻璃效果而改 bundler。

## 6. 判定、发现格式及停止规则

最终按三行给结论：

1. **维修：PASS / FAIL / NOT_VERIFIED**，附 R01–R09。任何确认的本轮必修缺陷残留为 FAIL；关键证明缺失为 NOT_VERIFIED；两者都有时 FAIL 并列出缺口。
2. **调查：完成 / 部分完成**，附 C01–C08、实际容器/子视图/元素统计与未检查列表；不得用观察状态数当界面总数。
3. **全应用统一：已达到明确约定目标 / 尚有保留或新增建议 / 无法判断**，列出具体 S2/S4/S5；不把“仍使用专用 CSS”直接等价为不统一，也不把保留的独立外观算已统一。

仅 R 全部适用项通过且原 C 表满足完成条件，才能宣布本次“补查并维修”整体完成。维修可以单独通过而调查仍部分完成，必须保留这两个结论。

发现格式：`[优先级][Rxx / 原 Axx 或 Cxx] 文件:行号 → 入口/状态 → 实际结果 → 既定要求 → 最小修正与复测`。美观建议不强行标 P2；尚未复现的疑点列未验证。

禁止新增全局样式平台、完整历史测试全绿、跨机/真实 Host 持久化、录像或复杂证据解析器作为本次通过门槛。独立审核判断证据含义，结构检查只能验证存在性/身份/明确状态，不能推断真实旅程发生。

同一任务连续两次修复/复审失败后，停止自动修复调度，向用户说明简化/拆分/继续选项；审核者不自己开启第三轮。支持脚本超过约 500 行或原审核基线两倍时指出范围风险，不用不断加断言扩大任务。
