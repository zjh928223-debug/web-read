# 预习生词轻量筛选与正文隔离设计

## 目标

以个人工具的轻量标准改善“预习生词”：

- 默认保留大致 B2 及以上词汇、新闻关键词和少量明确固定表达。
- 排除常见基础词、常见变形和缩写。
- 专有名词继续进入预习结果，但不进入 SRS。
- 预习词默认不在正文显示；用户可通过现有开关主动显示或隐藏。
- 隐藏手工轻回填导入、导出按钮，保留其底层能力。

## 实现范围

### 1. 本地候选筛选

在 `src/services/vocabulary/preview-scan.js` 内完成轻量筛选，不增加网络请求或外部词库：

- 扩充常见基础词集合，覆盖用户反馈的 `bus`、`three`、`bay`、`sun`、`car`、`hour`、`video` 等类型。
- 对常见缩写和简单词形进行归一，避免 `he'll`、`happened`、`recovering` 等仅因表面形式不同而绕过基础词过滤。
- 将词频从主导因素降为次要排序因素。
- 保留较难内容词和新闻主题词。
- 仅通过一份小型明确白名单识别 2–4 词新闻固定表达；不生成任意 n-gram。
- 保留现有最大候选数量限制。

该规则只追求“大致 B2+”的实用效果，不承诺完整 CEFR 分级。

### 2. 专有名词与 SRS

- 专有名词继续以独立分组显示在预习窗口。
- 保持现有 `preview_proper_noun` 排除逻辑，预习产生的专有名词不进入 SRS。
- 添加回归断言，防止后续修改破坏该边界。

### 3. 正文显示隔离

保留现有“显示预习词/隐藏预习词”按钮，默认关闭。

当前粗体泄漏的根因是：手动 AI 解释导入会先合并历史生成结果，再用合并后的全部项目重建 `markedMap`，其中包含 `preview-scan` 项。

修复方式：

- 保存和合并预习解释的现有流程不变。
- 手动轻回填/AI 解释导入重建正文标记时，过滤 `preview-scan` 项。
- 用户手动标记的项目继续进入 `markedMap` 并显示粗体。
- 预习词仅在用户主动打开预习开关时，通过 `previewVocabularyWordIndexes` 显示提示；关闭时清空提示位置。

### 4. UI 精简

从 `index.html` 移除：

- “导出轻回填模板”按钮。
- “导入轻回填结果”按钮。

保留隐藏文件 input、轻回填模块及导入导出函数，避免影响“AI解释标注”和已有内部流程。

## 验证

- 基础词、常见变形和缩写不会进入预习候选。
- 较难词、新闻关键词和白名单固定表达仍可进入候选。
- 专有名词进入预习，但不进入 SRS。
- 手动 AI 解释不会把历史预习词加入 `markedMap`。
- 预习词开关仍能独立显示和隐藏提示。
- 两个轻回填按钮不再出现在页面，底层模块仍通过原有专项检查。
- 运行相关词汇预习、轻回填、DOM、交互、Vite 与构建验证。

## 非目标

- 不引入完整 CEFR 词库或新依赖。
- 不增加额外 AI 筛词请求。
- 不修改 IndexedDB schema。
- 不删除轻回填底层功能。
- 不进行无关重构。
