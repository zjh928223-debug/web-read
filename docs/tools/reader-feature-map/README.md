# 阅读器功能地图

直接双击本目录的 `index.html`，在本机浏览器打开。Codex 内置浏览器不允许直接访问 `file://` 页面。无需启动阅读器或后端，也无需安装依赖。目录内四个页面文件应放在一起。

第一版用途是盘点与取舍，不执行产品功能，不读取阅读器数据，不调用后端，不修改阅读器存储。新增文件不接入 `index.html`、Vue、CSS 或构建入口，因此可以与 UI 收口并行。

## 操作

- 左侧按用户目的折叠功能，搜索名称、入口、行为、源码依据和备注；右侧展开行为详情。
- 默认一次展开一组；首屏只突出名称、简短用途和“你的判断”。操作条件、备注整理、关联功能、数据及代码依据按需展开。
- 筛选、全部展开/折叠、新增想法位于“目录工具”；导入导出位于右上角“更多”。
- 按钮与快捷键放在同一个功能下，条件分支放在详情中。
- 标记保留、疑似无用、重复、合并、拆分或新增；填写原因、拟调整名称及归并目标。
- 关联功能按钮会清除搜索与筛选，定位对应节点。
- “新增想法”放入选定功能组，明确标为未实现。
- 意见自动保存到当前浏览器独立键 `readweb.feature-map.opinions.v1`。不同浏览器、地址或移动目录后可能无法共享；请导出 JSON 备份。
- JSON 用于恢复或转移；导入会合并，已有同一功能的意见以导入文件为准，其它意见保留。整个文件验证通过后才修改当前意见。
- Markdown 整理清单只导出已有意见的条目，可用来讨论后续变更。没有执行删除、重命名或合并产品功能。

## 确认范围

2026-10-03 人工整理的当前源码快照。覆盖主要材料、播放、标注、生词、学习、设置与过时入口，以及部分自动行为。不是全应用交互覆盖完成报告。

“关键逻辑已查代码”表示已阅读相关处理器并整理关键条件；不保证全部上下游依赖已核对。“入口已核对”条目的完整调用链、数据边界仍需补核对。所有阅读器真实旅程保留 `NOT_VERIFIED`；地图自己的浏览器检查不代替阅读器旅程。

当前 UI 收口可能继续改变源码。目录不会自动跟踪变化；更新 `catalog.js` 时保持稳定功能 ID，可保留意见。确认后的拆分或合并应单独安排产品变更。已退役的 notes/cloze 等能力未作为当前功能重新引入。

## 文件与验收

- `index.html`：独立入口与新增想法对话框。
- `styles.css`：仅供地图使用的样式。
- `catalog.js`：人工功能目录、条件分支、数据影响、关联及源码依据。
- `app.js`：树、搜索、详情、独立意见存储与导入导出。

验收范围：页面加载、树展开/折叠、搜索筛选、详情与关联定位、意见与备注、刷新恢复、新增想法、JSON/Markdown 导出、有效导入和无效导入不破坏原意见，以及桌面/手机布局。无需跑阅读器全量构建或修改其正式验证入口。
